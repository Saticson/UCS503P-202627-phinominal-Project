\begin{abstract}
This report documents the completed Final Stage implementation, empirical evaluation, and verification of \textbf{Sukio}, an end-to-end Machine Learning Solution Ecosystem engineered for academic course UCS503P (Software Engineering) at Thapar Institute of Engineering and Technology. Sukio implements a unified three-tier operational funnel: \textbf{Build} (automated baseline modeling and embedded AutoML), \textbf{Buy} (curated solution marketplace with verified pre-trained model cards and asset downloads), and \textbf{Hire} (scoped expert commission requests and competitive proposal bidding). In this final milestone, the platform eliminates simulated mock endpoints by embedding a native \textbf{Java Machine Learning Engine (Smile 3.0)} for multi-tree tabular model training, genuine Gini feature importance computation, and binary model artifact serialization ($>200$\,KB), alongside an embedded \textbf{Microsoft ONNX Runtime} deep learning engine for live computer vision inference on MNIST and industrial defect benchmarks. The entire platform is validated through rigorous end-to-end automated Playwright integration test suites with zero external runtime dependencies.
\end{abstract}

\section{Introduction and Problem Definition}
Acquiring production-grade machine learning models presents prohibitive technical and economic friction for non-specialist engineers and resource-constrained enterprises. Standard public model repositories lack rigorous hardware-runtime verification, benchmark audit reproducibility, and seamless end-to-end execution pipelines.

Sukio formalizes machine learning acquisition into a structured, three-tiered decision funnel:
\begin{enumerate}[leftmargin=0.7cm]
  \item \textbf{Tier 1 (Build):} For users with proprietary tabular datasets, Sukio delivers an automated baseline discovery engine. It imputes missing values, trains multi-model ensembles (Random Forest, Decision Tree, Gradient Tree Boost), and calculates exact feature importances.
  \item \textbf{Tier 2 (Buy):} For standard tasks where training from scratch is uneconomical, Sukio provides an auditable Solution Marketplace featuring pre-trained, verified model cards, latency specifications, and direct binary weight downloads.
  \item \textbf{Tier 3 (Hire):} When specialized domain constraints (e.g., custom sensor cameras, edge FPGA hardware constraints, regulatory monotonicity) exceed catalog offerings, clients publish scoped Requests for Proposals (RFPs) on the Active Commission Board where certified ML practitioners bid with formal delivery timelines.
\end{enumerate}

\section{Solution Marketplace: The Buy Funnel}
The marketplace subsystem (\texttt{/marketplace}) addresses the second tier of the acquisition funnel:
\begin{itemize}[leftmargin=0.7cm]
  \item \textbf{Persistent Catalog JPA Entity:} Model listings are persisted in database table \texttt{marketplace\_listings} via \texttt{MarketplaceListingEntity} and queried through \texttt{MarketplaceListingRepository}, supporting indexed filtering by modality (\texttt{COMPUTER\_VISION}, \texttt{TABULAR}) and task type.
  \item \textbf{Automated Catalog Seeding:} On system startup, \texttt{MarketplaceDataInitializer} populates verified reference models, including ResNet-50 ImageNet Classifiers, YOLOv8 Defect Detectors, MobileNet-V3, and XGBoost Credit Risk models.
  \item \textbf{Verified Audit Specs \& Model Cards:} Dedicated detail views (\texttt{/marketplace/\{id\}}) display model architecture, batch input dimensions, inference latency (e.g., 14\,ms), accuracy benchmarks, and licensing.
  \item \textbf{Binary Artifact Download API:} An authenticated endpoint \texttt{GET /api/marketplace/\{id\}/download} serves physical model binaries with proper \texttt{Content-Disposition: attachment} headers.
  \item \textbf{Seller Solution Publishing Portal:} Sellers can publish new specialized architectures through an interactive modal dialog with client-side form validation.
\end{itemize}

\section{Expert Commission Board: The Hire Funnel}
When automated sweeps and catalog solutions do not meet stringent operational boundaries, clients engage the \textbf{Hire} funnel (\texttt{/hire}):
\begin{itemize}[leftmargin=0.7cm]
  \item \textbf{RFP Commission Publishing:} Requesters specify organization details, modality, task type, latency targets, and allocated budget (e.g., \$2,500 for low-power edge FPGA vision). Submissions persist in \texttt{expert\_commissions} table.
  \item \textbf{Expert Bidding and Proposal Workflow:} Verified ML engineers inspect live requests on the board and submit competitive bids through a proposal modal dialog. Each bid records expert name, email, proposed cost, delivery days, and methodology text in \texttt{commission\_proposals}.
  \item \textbf{Lifecycle State Machine:} Requests dynamically update from \texttt{OPEN} to \texttt{MATCHED} upon receipt of qualified proposals, rendering real-time proposal counters on the client dashboard.
\end{itemize}

\section{Embedded Java Machine Learning Engine}
To eliminate external runtime dependencies and mock simulation fallbacks, we integrated Haifeng Li's \textbf{Smile (Statistical Machine Intelligence and Learning Engine)} library directly into the Java control plane:
\begin{itemize}[leftmargin=0.7cm]
  \item \textbf{Automated Tabular Preprocessing:} \texttt{SmileDataPreprocessor} inspects uploaded CSV files, detects feature data types, performs missing value imputation, and maps string categorical targets into discrete integer labels ($0 \dots K-1$).
  \item \textbf{Multi-Tree Ensemble Training:} \texttt{SmileTrainer} executes asynchronous training runs across three distinct algorithms: Random Forest (\texttt{smile.classification.RandomForest}), Decision Tree (\texttt{smile.classification.DecisionTree}), and Gradient Tree Boost (\texttt{smile.classification.GradientTreeBoost}).
  \item \textbf{Genuine Gini Feature Importance:} Rather than serving static heuristic numbers, \texttt{SmileTrainer} extracts exact Gini split importances via \texttt{model.importance()} and normalizes them into relative contribution ratios for model explainability.
  \item \textbf{Binary Artifact Serialization:} Models are serialized as genuine binary files (\texttt{.bin}) to \texttt{storage/models/} using \texttt{smile.io.Write.object()}. Model artifacts range from 2.1\,KB (Decision Tree) to 270\,KB (Random Forest), verifying true weight persistence.
  \item \textbf{Live Tabular Inference:} In \texttt{PredictionService}, \texttt{SmileInferenceEngine} deserializes the binary model, constructs a typed \texttt{Tuple} from user-supplied feature JSON, and executes sub-millisecond scoring.
\end{itemize}

\section{Deep Learning Computer Vision via ONNX Runtime}
For visual diagnostic workflows, Sukio embeds the \textbf{Microsoft ONNX Runtime Java API (1.18.0)}:
\begin{itemize}[leftmargin=0.7cm]
  \item \textbf{ONNX Environment \& Session Management:} \texttt{OnnxVisionEngine} manages a singleton \texttt{OrtEnvironment} and loads bundled model \texttt{mnist-8.onnx} from classpath resources and local storage.
  \item \textbf{Image Preprocessing \& Tensor Normalization:} Uploaded images (or benchmark test patterns) are converted to 28$\times$28 single-channel grayscale rasters and transformed into 4D floating-point tensors of shape $[1, 1, 28, 28]$ with pixel intensities normalized to $[0.0, 1.0]$.
  \item \textbf{Softmax Classification:} \texttt{OrtSession.run()} computes raw output logits, over which numerically stable softmax evaluates multi-class probabilities, yielding genuine confidence outputs (e.g., 98.9\% on handwritten digits).
\end{itemize}
